# Vault guide — finding, trusting, and growing D:\AI\DesignVault

## Layout

```
D:\AI\DesignVault\
  INDEX.md                     master index — TRUE on-disk counts, regenerated by tooling
  uiverse\<category>\<author>__<slug>\    markup.html + style.css + meta.json
  codepen\<category>\<author>__<slug>\    markup.html + style.css + script.js + meta.json
  catalogs\codemyui.json                  curation catalog (post → pen mapping + tags)
  catalogs\codemyui_pens.txt              pen feed for the codepen harvester
  catalogs\user_pens.txt                  owner-supplied pen picks
  _tools\                                 harvesters + indexer + state.json (resume state)
  _raw\                                   staging only — excluded from indexes and counts
```

Every item's `meta.json` carries: `source_url`, `site`, `author`, `title`, `category`,
`tech`, `license`, `license_evidence` (+ uiverse items keep the per-post `license_text`).
**An item without source + license is malformed and fails the index build** — that is the
honesty machinery, do not weaken it.

## Provenance (what makes an item usable)

- **uiverse.io** — the site footer states: "All content (UI elements) on this site are
  published under the MIT License" (linked to <https://opensource.org/license/mit>);
  post pages additionally embed a per-author MIT text, saved into `license_text`.
- **CodePen** — public pens are MIT per CodePen's licensing documentation:
  <https://blog.codepen.io/documentation/licensing/>. Private/deleted pens return a
  "Pen Not Found or Not Available as a Resource" sentinel — the harvester rejects it.
- **codemyui.com** — curation only; rights sit with the underlying pen author, so code is
  always harvested from the pen, never from codemyui's pages.
- **cssbuttons.io** — curation only, same rule. ⚠ **CORRECTION (2026-08-31):** this guide
  used to call it "uiverse's own sister site, same MIT footer". **It has no MIT footer.**
  Its own footer reads *"© 2026 Adam Giebl, All rights reserved"*, and `/license`,
  `/terms`, `/about` are all 404. What it actually is: a hand-picked window onto
  uiverse.io by the same author — all **116** curated designs link to their
  `https://uiverse.io/<author>/<friendlyId>` post (**116/116 confirmed**), and its payload
  mirrors that post's code **byte-identically** (measured: 107 identical, 0 different).
  So rights sit with the uiverse author under uiverse's MIT, items are saved into the
  `uiverse/` tree with the uiverse URL as `source_url` plus `discovered_via:
  cssbuttons.io`, and a design whose uiverse post is gone (3 of 116 were 404) is refused.
- **MIT component repos** (added 2026-08-31, imported not scraped — `git clone` gives the
  exact source and the LICENSE file *is* the evidence). Each was checked against both the
  repo's own LICENSE and GitHub's API `license.spdx_id`:
  **markmead/hyperui** (MIT © Mark Mead — 560 standalone Tailwind examples),
  **ekmas/neobrutalism-components** (MIT © Samuel Breznjak — 92 registry components,
  the neobrutalism gap), **themesberg/flowbite** (MIT © Bergside Inc. — 631 examples).
  Clones live in `_repos\` (excluded from the index); each item stores the full
  licence text in `license_text`.
- **preline.co** (added 2026-09-01) — **610 components**, and the only source here that
  is *not* plain MIT. Preline UI is **dual licensed: MIT + a "Preline UI Fair Use
  License"** (one file: `github.com/htmlstreamofficial/preline/blob/main/LICENSE`; the
  site's own page is titled *"License | MIT and Fair Use Terms"*). It is free for personal
  and commercial use, and redistribution is allowed **on three conditions**, all of which
  each item satisfies: both licence texts travel with the code (`license_text`), no notice
  is altered, and attribution links to the repo (`attribution`). The one prohibition:
  do not use it to build a product that competes with Preline UI. ⚠ GitHub's API reports
  this repo as `NOASSERTION` — that means "not a plain standard licence", so the file has
  to be read, not that it is unusable.
- **freefrontend.com** — curation only, same rule as codemyui: the code comes from the
  underlying pen. Its previews name the pen by slug in `data-name="…"` with no owner, so
  `harvest_codepen.py` resolves the real author through CodePen's oEmbed API before saving.
- MIT obligations: keep the attribution that `meta.json` carries; shipping a translated
  MECHANIC into original Compose code in an invented direction is not copying a work, but
  when a vault item's look is reproduced closely, carry its attribution into the project —
  and a closely-reproduced look must still pass the Slop Detector (S16 flags an
  un-restyled vault look); the doctrine treats close reproduction as a near-never event.

## Finding designs

**Search by concept first** — with thousands of items, browsing an index is the slow path:

```bash
python _tools\find_design.py glass card          # words across tags/title/description
python _tools\find_design.py --tag neumorphism --category buttons --limit 20
python _tools\find_design.py --category loaders --tech css --sort newest
python _tools\find_design.py --tags-list         # every tag, most used first
```

It walks the meta.json files on disk (no cached index, so it cannot go stale) and **exits
1 on a genuine miss** — that means generate the design, not settle for a near-match.

Then:

1. Open `D:\AI\DesignVault\INDEX.md` for live counts per site/category.
2. Open the category `INDEX.md` (e.g. `uiverse\cards\INDEX.md`) — one line per item with
   title, tech, license, source link, files.
3. Open the item folder; read `style.css` for the mechanic; translate via
   `css-to-compose.md`.

### The HTTP engine (2026-08-31) — why harvesting is now ~10x faster

uiverse.io and cssbuttons.io are both **Remix** apps: the server HTML carries
`window.__remixContext`, and a post's payload holds its **html, css, type, isTailwind,
author and description** outright. The per-author MIT text sits in a readonly `<textarea>`
in the same HTML. So no browser render is needed — `harvest_uiverse.py --engine http`
(the default) is one plain GET per listing page (34 posts) and one per post.
`--engine browser` keeps the old stealth path as a fallback if that payload ever changes.
Parsing lives in `common.py` (`extract_remix`, `remix_loader`, `http_get`,
`mit_text_from_html`); a balanced-brace scan, never a regex — the payload contains braces
and quotes inside its strings.

Each item now also stores the author's own **`tags`** ("hover effect", "neumorphism",
"3d", "glass", "trash", "minimal"…) plus `created_date` and `origin` — that is what makes
the vault searchable by concept instead of by filename. Items harvested before this change
have no tags: `--refresh-meta` re-fetches exactly those and rewrites them.

Three traps found the same day:

1. Category listings mix in **ad slots** shaped `{"id": "uiverse-design-4"}` with no
   `friendlyId` — skip them or the harvester crashes on the first page.
2. **`/notifications` is a 404** even though 23 notification posts exist. They only arrive
   through the mixed `elements` feed, which is why `--categories elements` files each
   design under its own type folder.
3. **Browse listings are CAPPED, and the site's own counts prove it.** The root payload
   reports **7,418** designs, but `/elements` stops returning posts after **page 131**
   (~4,456), and per-category listings cap lower still — `/tooltips` yields 87 of its 136.
   The route that reaches the tail is the **author profile**: `/profile/<username>` returns
   that author's whole catalogue in one request (vinodjangid07: 130 posts, no pagination).
   Measured after a full category sweep, 91 of those 130 were still missing. So
   `--by-author` is not an extra — it is the only complete route.

`_tools\state.json` remembers every harvested item — re-runs skip them, so growth toward
the thousands target is incremental and safe. Politeness delays are built in; do not
strip them.
